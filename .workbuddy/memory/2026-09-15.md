## 前端浏览器级端到端验收（§59/§71）打通 —— 抓到 3 个真 bug

`tools/e2e_browser_check.mjs`（Edge + CDP + swiftshader，零依赖）**19 PASS / 0 FAIL / 1 SKIP**。
目视截图已确认：mini_arm 5 links / 3 可动关节 / 关节轴 / EE 标记 / 世界网格全部正确。

### bug 1（最严重）：`data-*` 属性让整个 3D 场景崩掉 —— 页面全黑
- `RobotScene.tsx` 的 `<group data-kind={...} data-id={...}>`。
- 根因：**`@react-three/fiber` 的 `diffProps` 里 `if (key.includes("-")) key.split("-")`**，
  于是 `data-kind` → `["data","kind"]` → `applyProps` 执行
  `instance.data.kind` → `instance.data` 是 `undefined` → **TypeError**。
- 症状极其误导：报错栈只有 `chunk-*.js` 与 `<group>`，**看不到本文件**；
  ErrorBoundary 捕获后整树重挂载 ⇒ `#root` 空、`canvas`/`.panel` 全查不到 ⇒
  所有 DOM 断言一起失败，看着像"后端没起"。
- ⇒ **Three.js fiber 元素上的属性名不得含 `-`**。用 `name` 或 `userData`（对象）。
- 文件里原来那段"`data-*` 在静态渲染里会保留"的注释**只对 DOM 渲染器成立**，
  正是它把 bug 引进去的 —— 已重写为警告。

### bug 2：`showAxes` 提了但没往下传 —— 「关节轴」复选框是死的
- `RobotScene.tsx` 里 `showAxes` 只用于 `{!showAxes && <group name="__axes_hidden"/>}`，
  **从未传给 `NodeView`** ⇒ `AxisIndicator` 恒渲染，开关无效。
- 修法：把 `showAxes` 透传进 `NodeView`，门控 `AxisIndicator`。
- ★ 这个 bug 暴露"DOM 断言 + 像素个数阈值"这套判据的弱点：
  原来写的是 `|after.nonBg - before.nonBg| > 50`，而失败时读数恰好是 `0 → 0`
  （因为 bug 1 让整个 canvas 空白），**两个 bug 叠在一起互相掩盖**。

### bug 3（探针侧）：`gl.readPixels` 在帧外读 ⇒ 恒全 0
- r3f 没开 `preserveDrawingBuffer`，每帧 present 后绘制缓冲被清空。
- **实测对照（唯一变量 = 读的时机）**：
  ```text
  A) 帧外 readPixels           → nonzeroPixels =      0   （gl.getError() 仍是 0，不报错！）
  B) rAF 回调内 readPixels     → nonzeroPixels = 149480
  C) 帧外 canvas.toDataURL()   → 6162（≈ 空白图）
  ```
- ⇒ 探针里所有读像素必须包在 `requestAnimationFrame` 内。
- 这个坑的误导性：判据失败表现为"页面全黑"，而 `Page.captureScreenshot`
  （走 compositor 不走 GL 缓冲）**同一次运行的截图明明有内容** ——
  两者矛盾时人容易去怀疑渲染/相机/坐标，方向全错。
  **规则：截图有内容而像素读数为 0 ⇒ 先怀疑读的时机。**

### 探针判据改进（记忆铁律二/四的又一次应用）
- 内容阈值 `2%` → `0.5%`：canvas 只占页面一部分，2% 是拍脑袋的数字，

### ★ 最重要发现：2R 往返的正确判据是**分类**，不是**容差**

朴素往返断言对 mini_arm 有约 48% 位形"失败"，但**不是 bug**。定律（全网格
11³ 双向验证，交叉项全为 0）：

```text
令 d(θ1,θ2) = L1·cos θ1 + L2eff·cos(θ1+θ2)   （TCP 沿基座轴的有符号投影）

d > 0  TCP 在基座轴前方 ⇒ 同分支解，位置与姿态**都精确闭合**
d < 0  TCP 在基座轴后方 ⇒ atan2(TCP) 必然 = base_yaw+π，
       IK 返回"从反侧够到同一物理点"的等价位形：
         位置精确（7e-17 m），姿态差一个**精确 180° 旋转**
         该解的 elbow 与源**逐位相同**，只 yaw 差 π、shoulder 被重解
d = 0  elbow≡0 退化 ⇒ 两分支合并，IK 标 [degenerate]，位姿仍精确闭合

分类计数：d>0&姿态一致 979 | d>0&180° 0 | d<0&180° 286 | d<0&姿态一致 0
          elbow≡0 44 | 无法解释 0
```

**判据（Phase 3 的核心结论）**：看相对旋转 `ΔR = R_ik·R_src⁻¹` 的 **w 分量**：

```text
|ΔR.w| ≈ 1  ⇒ 同姿态      → 要求 Δquat ≤ 1e-12
|ΔR.w| ≈ 0  ⇒ 精确 180°   → 合法的"反侧等价位形"
其它         ⇒ 中间态      → **判失败**（不许存在）
```

**为什么不能用容差**：`Δquat < TOL` 要过就得把 TOL 设到 π 以上，
于是 1° 的系统性错误也被放过。分类要求**每个位形都能被机制解释** ——
将来若改坏坐标约定，大量位形掉进"其它"桶，验收立刻红，
**即使位置误差仍在 1e-12 内**。

**踩过的三次错判**（都记进脚本与 skill 了）：

1. 猜想"解位姿 = 源位姿绕基座 Z 转 π" ⇒ 左乘 `Rz(π)` 补偿后残差 0.970 ❌
   右乘 `src·Rz(π)` 残差 1.198 ❌；共轭 `Rz(-π)·src` 残差 0.970 ❌
   **实测 ΔR 的 w 恒为 0（恒 180°）但转轴随位形变化**
   （[0.021,0.016,0.9997] / [0.101,0.451,-0.887] …）⇒ **不存在固定补偿**。
2. 把 `Rz(π)` 也算进了**位置** ⇒ `d<0` 组位置差变 0.89 m，`min()` 挑错配对
   ⇒ 报出 **Δpos=0.89 m 的假失败**。正确做法：**位置永远直接比**，姿态才补偿。
3. 自写诊断把 44 个位形分类为 "fail"，实际引擎**完全正确**
   （`dp=0, dq=0, ori_err=0`）—— 根因是我诊断脚本 `except` 分支的 `break`
   吞掉后续比较。**测量工具错了，不是引擎错了。**

   （它是**模块名**，不是硬编码格式名）⇒ 恒 FAIL。
   ✅ 判据改为**只扫字符串字面量**（`tokenize.STRING`）且要求
   **恰好等于**格式名。
   ⚠️ 注意这是 §4.12 的**极性反转**：那里字符串是噪声要剥离，
   这里字符串**就是目标**，不能剥离。
② **扫描器没元测试**：`assert not hard_lits` 在扫描器坏掉时也通过
   ⇒ 配 `string_literals('x = "mjcf"\ny = "urdf"\n')` 必须抓到两个。
   另加 docstring 元测试（docstring 也是 STRING token，判据不受影响
   但会淹掉打印，故过滤 `"\n" in body or len(body) > 120`）。
③ **合成模型被 Validator 拒**：`report.ok` 是 False，三条真问题
   —— `tree.base_frame_empty`（`base_frame` 默认 `""`）、
   `tree.multiple_roots`（两个 Link 的 `parent_joint` 都是 None）、
   `joint.no_position_limit`（revolute 没给 `JointLimits`）。
   ✅ 合成 loader 产出的模型也要过**同一套** Validator；判据别只断言
   "加载成功"，要断言 `report.ok is True`。

## 前端浏览器级端到端验收（§59/§71）打通 —— 抓到 3 个真 bug

`tools/e2e_browser_check.mjs`（Edge + CDP + swiftshader，零依赖）**19 PASS / 0 FAIL / 1 SKIP**。
目视截图已确认：mini_arm 5 links / 3 可动关节 / 关节轴 / EE 标记 / 世界网格全部正确。

### bug 1（最严重）：`data-*` 属性让整个 3D 场景崩掉 —— 页面全黑
- `RobotScene.tsx` 的 `<group data-kind={...} data-id={...}>`。
- 根因：**`@react-three/fiber` 的 `diffProps` 里 `if (key.includes("-")) key.split("-")`**，
  于是 `data-kind` → `["data","kind"]` → `applyProps` 执行
  `instance.data.kind` → `instance.data` 是 `undefined` → **TypeError**。
- 症状极其误导：报错栈只有 `chunk-*.js` 与 `<group>`，**看不到本文件**；
  ErrorBoundary 捕获后整树重挂载 ⇒ `#root` 空、`canvas`/`.panel` 全查不到 ⇒
  所有 DOM 断言一起失败，看着像"后端没起"。
- ⇒ **Three.js fiber 元素上的属性名不得含 `-`**。用 `name` 或 `userData`（对象）。
- 文件里原来那段"`data-*` 在静态渲染里会保留"的注释**只对 DOM 渲染器成立**，
  正是它把 bug 引进去的 —— 已重写为警告。

### bug 2：`showAxes` 提了但没往下传 —— 「关节轴」复选框是死的
- `RobotScene.tsx` 里 `showAxes` 只用于 `{!showAxes && <group name="__axes_hidden"/>}`，
  **从未传给 `NodeView`** ⇒ `AxisIndicator` 恒渲染，开关无效。
- 修法：把 `showAxes` 透传进 `NodeView`，门控 `AxisIndicator`。
- ★ 这个 bug 暴露"DOM 断言 + 像素个数阈值"这套判据的弱点：
  原来写的是 `|after.nonBg - before.nonBg| > 50`，而失败时读数恰好是 `0 → 0`
  （因为 bug 1 让整个 canvas 空白），**两个 bug 叠在一起互相掩盖**。

### bug 3（探针侧）：`gl.readPixels` 在帧外读 ⇒ 恒全 0
- r3f 没开 `preserveDrawingBuffer`，每帧 present 后绘制缓冲被清空。
- **实测对照（唯一变量 = 读的时机）**：
  ```text
  A) 帧外 readPixels           → nonzeroPixels =      0   （gl.getError() 仍是 0，不报错！）
  B) rAF 回调内 readPixels     → nonzeroPixels = 149480
  C) 帧外 canvas.toDataURL()   → 6162（≈ 空白图）
  ```
- ⇒ 探针里所有读像素必须包在 `requestAnimationFrame` 内。
- 这个坑的误导性：判据失败表现为"页面全黑"，而 `Page.captureScreenshot`
  （走 compositor 不走 GL 缓冲）**同一次运行的截图明明有内容** ——
  两者矛盾时人容易去怀疑渲染/相机/坐标，方向全错。
  **规则：截图有内容而像素读数为 0 ⇒ 先怀疑读的时机。**

### 探针判据改进（记忆铁律二/四的又一次应用）
- 内容阈值 `2%` → `0.5%`：canvas 只占页面一部分，2% 是拍脑袋的数字，
  会把"渲染正确但相机较远"误判失败。要排除的是"空白帧"，不是"内容够小"。
- 交互判据从"**像素个数**变化 > 50"改成"**逐像素位图差异占比**"：
  个数极易被相机抖动/抗锯齿/网格线淹没 ⇒ 阈值不是恒真就是恒假。
  现在是"关掉后差异 > 0.1%"(证明生效) + "切回后差异 < 0.02%"(证明可逆)，
  **两个方向都要**，否则"开关把画面变黑"也能通过。
- 背景色基准从"左上角单点"改成"**四角中位数**"（左上角可能压在网格线上）。

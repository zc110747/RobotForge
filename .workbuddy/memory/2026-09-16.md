## 一键启动脚本 `start.bat`（新增，按用户需求交付）

新增仓库根目录 `start.bat`：纯 ASCII + CRLF，~35.9 KB / 865 行。
双击即用：自动建/修 venv、装 Python 与前端依赖（含 **vite**）、起后端与前端、
验证代理链路、打印访问地址；关窗口 = 停服务。所有退出路径都有 `pause`（`--no-pause` 可关）。

### 关键设计决策（别改回去）
- **后端入口必须是 `tools.serve_mujoco:app`**（注入 `mujoco_backend_factory`），
  不是 README 里那条 `backend.api.app:create_app --factory` —— 后者是 `MockBackend`。
- **前端显式走 `"%NODE_EXE%" "%VITE_JS%"`**，不调 `node_modules/.bin/vite.cmd`，
  避免被 PATH 上错误的 node 劫持（npm.cmd 与 PATH node 是两条独立解析链）。
- **单实例守卫用「端口占用」判据**，且**必须早于 `:check_ports`** ——
  否则 `check_ports` 会先把运行中的实例杀掉，"释放端口"，守卫永远轮不到。
- **只杀自己起的 PID**（`start-pids.txt`）+ `taskkill /F /T /PID`，
  绝不用 `/IM node.exe`（会误杀用户其它 node 进程；实测 4 个无关 node 全部存活）。

### 本轮修掉的两个真实缺陷（都是实测抓到的，不是推测）
1. **`--check` 会杀掉运行中的实例**（最严重）。
   原实现只跳过"启动步骤"，但 `:check_ports` 里的 `taskkill` 分支照跑 ⇒
   实测把正在服务的后端 PID 16572 + 前端 6372 一起杀了，两个端口全空，
   **而它同时还打印 "nothing is started"**。
   修法：`:check_ports` 按模式分叉，`--check` 走纯报告分支（只报 PID + 置 `PORT_BUSY`，
   绝不 taskkill）。判据从"起没起服务"改成"**会不会改变系统状态**"。
2. **失败横幅打了两次 + 退出码错误（0）**。
   在 `call` 进的子例程里 `goto <外部标签>` 跳出去，调用处的
   `if errorlevel 1 goto failed` 照样执行 ⇒ 两段横幅都打。
   改用嵌套括号块又踩第二个坑：**退出码变成 0**（明明预检没过）。
   修法：结论就地打印在 `:check_ports`，调用点用
   `if errorlevel 1 goto ports_failed` + 独立标签平铺写法（**别用括号块**），
   `--check` 分支直接 `exit /b 1`。

## 前端布局调换：3D 视口移到**左**，控制栏移到**右**（用户要求）

用户原话「建模和控制的位置换下，左边建模，右边操作栏，现在位置不适合控制」。

改动（2 个文件）：
- `frontend/src/App.tsx`：**调换 DOM 顺序** —— `<main className="viewport">` 在前，
  `<aside className="sidebar">` 在后。
- `frontend/src/styles.css`：`.sidebar` 的 `border-right` → **`border-left`**
  （侧栏换到右边后，分隔线必须跟着落到左边，否则会画到窗口最外沿）。

### 关键决策：靠 DOM 顺序，不靠 CSS 反转（别改回去）
**不用** `flex-direction: row-reverse` 或 `order`。原因：DOM 顺序同时决定
Tab 焦点顺序与读屏顺序，用 CSS 反转会让键盘用户按 Tab 时焦点先落在
右侧控制栏、再跳到左侧画布，与视觉顺序相反。视觉与语义必须一致。

### 验证方式：读真实 DOM 几何，不靠截图目测
临时 CDP 探针读 `getBoundingClientRect()`，实测（窗口 1416px 宽）：
```text
canvas  : left=0    right=1036   ← 视口在左
sidebar : left=1036 right=1416   ← 侧栏在右
domOrder: ["main.viewport", "aside.sidebar"]
borderLeft: 1px rgb(38,48,57)    borderRight: 0px
```
回归：`tsc --noEmit` 0 错；`vite build` 通过；4 个前端自检脚本全 PASS
（jointPanel / ws / ghost / render 124 项）；`e2e_browser_check.mjs`
**25 PASS / 0 FAIL / 0 SKIP**（拖滑块 → 实际值 0.0576 rad，闭环仍通）。

> 注：`e2e_browser_check.mjs` 只断言 `sidebar.class` 含不含 `collapsed`，
> **不**断言侧栏物理位置，所以本次调换不影响它 —— 但也意味着它**测不到**位置，
> 位置验证必须另写几何探针（见上）。

## 前端风格改版：对齐 MeArmPilot（用户要求，保持功能不变）

### 结构变化（App.tsx）
原来的 `.viewport` + `.sidebar` 之上又加了一层头、中间加了包裹层：

```text
div.app
├── header.appbar     新增：品牌 + 副标题 + Phase
├── div.toolbar       **从 .viewport 内部移到外面**（横贯整窗口）
└── div.body          新增包裹层
    ├── main.viewport （左）
    └── aside.sidebar （右）
```

工具条必须移出 viewport：否则它会被侧栏切断，而 MeArmPilot 的 chip 行是横贯顶部的。
e2e 用的是 `.toolbar input[type=checkbox]` / `.toolbar button`（**后代**选择器），
所以移出 viewport **不会**让检查落空 —— 实测 25/25 仍然 PASS。
